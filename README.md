# Кастомные патчи для Nova Video Player (aos-AVP)

В этой папке хранятся все доработки Nova в виде патчей, чтобы быстро переносить их на новые версии.
Каждый патч — это разница между upstream-ревизией (см. `export_patches.sh`) и рабочим деревом соответствующего репозитория.

## Список патчей

### 1. `01_medialib.patch` (MediaLib)
- **Коды языков** (`ISO639codes.java`): `getEnglishLanguageNameForLetterCode` не падает на некорректных кодах дорожек (`5.1`, `..`) — раньше `Locale.Builder` бросал `IllformedLocaleException`.
- **Закладки для неиндексированных потоков** (`ExternalBookmarks.java`)
  - Позиция просмотра TorrServe/AceStream/HTTP-потоков хранится отдельно от медиатеки. Ключ TorrServe — `hash + индекс файла`, поэтому смена IP/порта и параметров вроде `&play` его не меняют.
  - Старые формы ключей читаются и при следующем сохранении переносятся на канонический ключ.
  - `IndexHelper.java`: загрузка и сохранение этих закладок; поздние результаты скрапинга предыдущего видео отбрасываются; исправлен ключ кэша `ScraperTask`.
- **Заголовок потока до скрапинга** (`StreamTitleResolver.java`)
  - Показывается заголовок, переданный приложением (например, заголовок раздачи из TorrServe), как есть, без чистки — убираются только теги в квадратных скобках в самом начале (`[NUM] `). Если имя файла в URL задаёт серию (`/stream/Show.S04E07.mkv`), к нему добавляется номер: `<заголовок>  -  S04E07`; если номер уже есть в заголовке, он не повторяется.
  - Без заголовка показывается имя файла из URL (без `?query` и расширения видео).
  - Скрапится имя файла, как в upstream; после успешного скрапинга заголовок заменяется данными TMDb (`Звёздный путь: Странные новые миры  -  S04E07  -  <название серии>`).
- **Скрапер**
  - `TransliterateUtils.java`: обратная транслитерация по общим правилам, без исключений для отдельных слов и без попыток угадать опечатки (`Kholop` → `Холоп`, `Moya` → `Моя`, `Ekipazh` → `Экипаж`, `Otchayanie` → `Отчаяние`). Однозначно не восстановимое (`ts` — «ц» или «тс», пропущенный мягкий знак: `nelzya` → «нелзя») оставляется нечёткому поиску TMDb и оценке совпадений. Единственный дополнительный вариант — разделительный мягкий знак перед йотированной гласной после согласной (`Druzja` → «Друзя», затем «Друзья»); берётся вариант, для которого TMDb находит точное совпадение названия. Русские правила включаются только при русском языке скрапинга (или русской системной локали, если язык не задан). В `MovieScraper3` транслит запрашивается в TMDb только если остальные варианты ничего не нашли; в `SearchShow` — при нулевом результате.
  - `ParseUtils.java`: `splitBilingualTitle` разделяет склеенные русско-английские названия; нумерация вида `01.Название` (с ведущим нулём) отрезается, а `21.Jump.Street`, `2.Fast.2.Furious`, `007.Skyfall` — нет; расширен список релизного мусора (`webdl`, `camrip`, `telecine`...).
  - `MovieScraper3.java`/`ShowScraper4.java`: поиск по частям двуязычного названия. В `MovieScraper3` расстояние результата — лучшее расстояние Левенштейна до любого написания названия (имя файла, его транслит, части двуязычного названия). При равном расстоянии порядок такой: год выпуска, ближайший к году из имени файла, даже если год не в скобках (год в начале имени не учитывается); затем, только при русском транслите, — совпадение оригинального названия с транслитом (`Svobodnoe padenie` → «Свободное падение» 2025, а не «Freefall» 1994, вышедший в России под тем же названием); затем порядок upstream.
  - Немецкий транслит (`ae` → `ä`) включается по языку скрапинга, а системная локаль учитывается только если язык не задан.
- Тесты: `StreamTitleResolverTest`, `ExternalBookmarksTest`, `TransliterateUtilsTest`, `TrackNamingTest`.

### 2. `02_video.patch` (Video)
- **Плейлисты M3U/M3U8** (`M3uParser.java`)
  - Поддержка `#EXTINF` с атрибутами (запятые внутри кавычек), BOM, CRLF, UTF-8 и windows-1251, относительных и корневых путей, ограничение размера, проверка HTTP-ответа. HLS-потоки (`#EXT-X-...`) передаются плееру как есть.
  - Плейлист также принимается через extra `videoList`/`titleList` (API MX Player).
- **Автоплейлист TorrServe**: при просмотре одного файла торрента (`/stream/<файл>?link=<hash>...`) плеер в фоне запрашивает плейлист по тому же пути с `.m3u` (`/stream/<файл>.m3u?link=<hash>&m3u`) — это подтверждённый рабочий эндпоинт TorrServe. Переключение и автопереход на следующую серию сохраняют заголовок раздачи.
- **Переключение видео с пульта**: Channel Up/Down, Page Up/Down, Media Next/Previous, клавиши G/H. Настройка «Кнопки следующее/предыдущее» позволяет вернуть им поведение upstream (скорость воспроизведения). Предыдущее видео ищется в папке, плейлисте, медиатеке и по сериям.
- **Заголовки**: один источник правды — сервис передаёт в UI исходный заголовок текущего элемента. При переходе к следующему файлу папки заголовок предыдущего не наследуется. Плейлист сбрасывается, если новое видео запущено без плейлиста.
- **Фоновый скрапинг TMDb**: метаданные неотскрапленного видео подтягиваются во время просмотра, но только для OSD и карточки «Сейчас играет». Результаты TMDb в базу не записываются, чтобы угаданное по имени потока совпадение не портило медиатеку (теги из найденного `.nfo` проиндексированного файла сохраняются, как в upstream).
- **Бейдж качества** (`VideoQualityBadge.java`): `[4K]`, `[1080p]`... и `HDR` рядом с заголовком в OSD.
- **Точная перемотка шагом** (`PlayerController.java`): фиксированный шаг (например +15 с) теперь всегда даёт одинаковый сдвиг — 4 нажатия вперёд дают ровно +1 мин, как в VLC.
  - Шаги копятся от цели предыдущей перемотки (`mNextSeek`), а не от позиции, которую плеер сообщает во время ещё идущей перемотки — иначе часть шагов терялась или удваивалась.
  - Удержание кнопки (`MSG_SEEK`) продолжает добавлять шаг только пока кнопка реально зажата; порог удержания поднят с 200 до 400 мс, чтобы обычное короткое нажатие не засчитывалось как долгое (раньше это добавляло лишний шаг после отпускания).
  - `clampSeekTarget()` не даёт цели уйти за начало или конец видео.
  - Двойной тап по краям экрана переиспользует ту же логику (`onSeek`), а не отдельный вызов `seekTo`.
- **Шаг перемотки** (2–60 с): настройка `seek_step`, используется кнопками влево/вправо и двойным тапом.
- **Затемнение на паузе** (`PauseScreensaver.java`): после заданного бездействия экран затемняется, часы непрерывно движутся по экрану, отскакивая от краёв (защита OLED). Любая кнопка или касание будят экран; громкость и Play работают сразу.
- **Русская локализация**: переведены все видимые пользователю строки и настройки, включая бэкап/восстановление медиатеки, алгоритмы изменения скорости звука, декодеры FFmpeg/MediaCodec, пропуск заставок IntroDB, параметры сортировки, расширенные настройки ТВ-интерфейса, статусы Trakt и OpenSubtitles, дескрипторы дорожек. Без перевода оставлены только технические значения: ключи настроек, URL, форматы строк, названия кодеков и форматов (`HDR10`, `PGS`...).
- **Прочее**: `build.gradle` подписывает release отладочным ключом, если нет `keystore.properties`; добавлен `gradlew.bat`.

- Тесты: `M3uParserTest`.

### 3. `03_root_core_mk.patch` (корень проекта)
- Сборка нативной части под Windows (`make` из w64devkit): пути с обратными слэшами, `ndk-build.cmd`, `$(MAKE)` вместо `make`.

### 4. `04_filecorelibrary.patch` (FileCoreLibrary)
- `FileUtils.stripUrlQueryAndFragment`: у HTTP(S)-ссылок имя файла и расширение берутся без `?query`/`#fragment` (`/stream/video.mkv?link=a.b&play` → `video.mkv`). У локальных и SMB-файлов символы `?` и `#` в имени сохраняются (`What?.mkv`).
- Тесты: `FileUtilsNameTest`.

### 5. `05_native_avos.patch` (native/avos)
- **Точная перемотка на заданный шаг**: `avos_mp_video.c` (`avos_mp_video_seek`) всегда ищет ключевой кадр НАЗАД от цели (`STREAM_SEEK_BACKWARD`), а не вперёд/назад в зависимости от направления. Поиск вперёд может перескочить цель на длину GOP, из-за чего одинаковый шаг (+15 с) каждый раз давал разный сдвиг на шкале. После посадки на кадр ffmpeg-декодер довыталкивает кадры точно до нужного времени.
  - `stream_video.c`: уточняющий проход (`_stream_play_n_frames`) теперь выполняется и при перемотке вперёд, а не только назад — убрано условие `old_time > target_ts &&` перед вызовом. Без этого перемотка вперёд могла останавливаться на первом попавшемся кадре после посадки, а не на точном целевом времени.
- `stream_parser_ffmpeg.c`: демуксер продолжает читать сеть, когда голодает видео (а не только звук), в пределах удвоенных лимитов очереди.
- `stream_sink_video_android3.c`: сильно опоздавшие кадры (> 200 мс) сбрасываются сериями до 30 штук, затем один кадр показывается, чтобы картинка не замирала при постоянно отстающем декодере.
- `codec_sfdec2.c`: пересинхронизация после паузы при расхождении аудио и видео больше 500 мс в любую сторону.

## Обновление Nova до новой версии

1. Обновите upstream (`git pull`, новый тег/ветка) в корне и сабмодулях.
2. Примените патчи (скрипт идемпотентен и пропускает уже применённые):
   ```powershell
   .\apply_patches.ps1
   ```
   *(или в bash: `./apply_patches.sh`)*
3. Если патч не применился, разрешите конфликты в соответствующем репозитории.
4. Обновите upstream-ревизии (`*_BASE`) в `patches/export_patches.sh` и перегенерируйте патчи:
   ```bash
   bash patches/export_patches.sh
   ```
   Не сохраняйте `git diff` через `>` в PowerShell: получится UTF-16, который `git apply` не читает. Скрипт пишет патчи средствами git (UTF-8, LF), а `.gitattributes` запрещает git менять в них концы строк.
5. Прогоните тесты:
   ```powershell
   cd Video
   .\gradlew.bat -x ndkBuild :FileCoreLibrary:testDebugUnitTest :MediaLib:testDebugUnitTest :testNoamazonDebugUnitTest
   ```
6. Соберите APK:
   ```powershell
   $env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
   $env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
   $env:ANDROID_SDK_ROOT = "$env:LOCALAPPDATA\Android\Sdk"
   $env:Path = "$env:JAVA_HOME\bin;C:\w64devkit\bin;$env:Path"
   cd Video
   .\gradlew.bat assembleNoamazonRelease
   ```
   Готовый APK для ТВ (`armeabi-v7a`) появится в `Video\build\outputs\apk\noamazon\release\`.
