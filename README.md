# Кастомные патчи для Nova Video Player (aos-AVP)

В этой папке хранятся все доработки Nova в виде патчей, чтобы быстро переносить их на новые версии.
Каждый патч — это разница между upstream-ревизией (см. `export_patches.sh`) и рабочим деревом соответствующего репозитория.

## Список патчей

### 1. `01_medialib.patch` (MediaLib)
- **Устойчивость к несовпадающей нативной библиотеке**
  - `MediaMetadata.java`: `getInt`/`getString`/`getBoolean`/... возвращают значение по умолчанию вместо `IllegalStateException: Wrong type`, если ключ отсутствует или имеет другой тип.
  - `LibAvos.java`: необязательные аудио-вызовы (`setAudioDecoder`, spatializer, скорость) не роняют плеер, если `libavos.so` старше Java-слоя; это всегда пишется в лог как предупреждение.
  - `ISO639codes.java`: `getEnglishLanguageNameForLetterCode` не падает на некорректных кодах языка (`5.1`, `..`).
- **Закладки для неиндексированных потоков** (`ExternalBookmarks.java`)
  - Позиция просмотра TorrServe/AceStream/HTTP-потоков хранится отдельно от медиатеки. Ключ TorrServe — `hash + индекс файла`, поэтому смена IP/порта и параметров вроде `&play` его не меняют.
  - Старые формы ключей читаются и при следующем сохранении переносятся на канонический ключ.
  - `IndexHelper.java`: загрузка и сохранение этих закладок; поздние результаты скрапинга предыдущего видео отбрасываются; исправлен ключ кэша `ScraperTask`.
- **Распознавание заголовков потоков** (`StreamTitleResolver.java`)
  - Из заголовка раздачи (`Во все тяжкие / Breaking Bad / Сезон: 1 / Серии: 1-7 из 7 [2008, WEB-DL]`) берётся локализованное название, из имени файла в URL (`/stream/Breaking.Bad.S01E03.mkv`) — сезон и серия. Результат: `Во все тяжкие / Breaking Bad  -  S01E03`.
  - Голый номер в начале имени файла (`04 - Cancer Man`) считается серией только при признаках сериала (сезон в заголовке/пути, слова «серия», «сезон»...), поэтому `21.Jump.Street` остаётся фильмом.
  - Отрезаются только расширения видеофайлов: `Mr. Robot` и `Слово пацана. Кровь на асфальте` не обрезаются.
  - Для фильмов сохраняется год (`[2010, BDRip]`), он передаётся скраперу.
  - `buildScraperFileName`: синтетическое имя для скрапинга потока по заголовку. Без заголовка скрапится реальный файл (работают `.nfo` и имена папок).
- **Скрапер**
  - `TransliterateUtils.java`: обратная транслитерация (`Kholop` → `Холоп`, `Moya` → `Моя`, `Ekipazh` → `Экипаж`). В `MovieScraper3` транслит запрашивается в TMDb только если остальные варианты ничего не нашли; в `SearchShow` — при нулевом результате.
  - `ParseUtils.java`: `splitBilingualTitle` разделяет склеенные русско-английские названия; нумерация вида `01.Название` (с ведущим нулём) отрезается, а `21.Jump.Street`, `2.Fast.2.Furious`, `007.Skyfall` — нет; расширен список релизного мусора (`webdl`, `camrip`, `telecine`...).
  - `MovieScraper3.java`/`ShowScraper4.java`: поиск по частям двуязычного названия и учёт транслита в оценке совпадений.
- **Ремаппинг путей** (`PackagePathRemapper.java`): пути постеров/миниатюр из базы другой сборки (`com.archos.mediacenter.video...`) переписываются на текущий пакет. Сравнение идёт по сегменту `/<пакет>/`, поэтому операция идемпотентна.
- Тесты: `StreamTitleResolverTest`, `ExternalBookmarksTest`, `TransliterateUtilsTest`, `TrackNamingTest`.

### 2. `02_video.patch` (Video)
- **Плейлисты M3U/M3U8** (`M3uParser.java`)
  - Поддержка `#EXTINF` с атрибутами (запятые внутри кавычек), BOM, CRLF, UTF-8 и windows-1251, относительных и корневых путей, ограничение размера, проверка HTTP-ответа. HLS-потоки (`#EXT-X-...`) передаются плееру как есть.
  - Плейлист также принимается через extra `videoList`/`titleList` (API MX Player).
- **Автоплейлист TorrServe**: при просмотре одного файла торрента (`/stream/...?link=<hash>`) плеер в фоне запрашивает `/playlist?link=...&m3u`. Переключение и автопереход на следующую серию сохраняют локализованное название раздачи.
- **Переключение видео с пульта**: Channel Up/Down, Page Up/Down, Media Next/Previous, клавиши G/H. Настройка «Кнопки следующее/предыдущее» позволяет вернуть им поведение upstream (скорость воспроизведения). Предыдущее видео ищется в папке, плейлисте, медиатеке и по сериям.
- **Заголовки**: один источник правды — сервис передаёт в UI исходный заголовок текущего элемента. При переходе к следующему файлу папки заголовок предыдущего не наследуется. Плейлист сбрасывается, если новое видео запущено без плейлиста.
- **Фоновый скрапинг TMDb**: метаданные неотскрапленного видео подтягиваются во время просмотра, но только для OSD и карточки «Сейчас играет». В базу они не записываются, чтобы угаданное по заголовку совпадение не портило медиатеку.
- **Бейдж качества** (`VideoQualityBadge.java`): `[4K]`, `[1080p]`... и `HDR` рядом с заголовком в OSD.
- **Шаг перемотки** (2–60 с): настройка `seek_step`, используется кнопками влево/вправо и двойным тапом.
- **Затемнение на паузе** (`PauseScreensaver.java`): после заданного бездействия экран затемняется, часы непрерывно движутся по экрану, отскакивая от краёв (защита OLED). Любая кнопка или касание будят экран; громкость и Play работают сразу.
- **Полная русская локализация**: переведены на русский язык 100% настроек и строковых ресурсов (бэкап/восстановление медиатеки, алгоритмы изменения скорости звука, декодеры FFmpeg/MediaCodec, пропуск заставок IntroDB, параметры сортировки, расширенные настройки ТВ-интерфейса, статусы Trakt и OpenSubtitles, дескрипторы дорожек).
- **Прочее**: `VideoMetadata` устойчив к некорректным метаданным; `PlayUtils` использует authority FileProvider текущего пакета; `MediaLibraryBackupService` ремапит пути после импорта; `build.gradle` подписывает release отладочным ключом, если нет `keystore.properties`; добавлен `gradlew.bat`.

- Тесты: `M3uParserTest`.

### 3. `03_root_core_mk.patch` (корень проекта)
- Сборка нативной части под Windows (`make` из w64devkit): пути с обратными слэшами, `ndk-build.cmd`, `$(MAKE)` вместо `make`.

### 4. `04_filecorelibrary.patch` (FileCoreLibrary)
- `FileUtils.stripUrlQueryAndFragment`: у HTTP(S)-ссылок имя файла и расширение берутся без `?query`/`#fragment` (`/stream/video.mkv?link=a.b&play` → `video.mkv`). У локальных и SMB-файлов символы `?` и `#` в имени сохраняются (`What?.mkv`).
- Тесты: `FileUtilsNameTest`.

### 5. `05_native_avos.patch` (native/avos)
- `stream_parser_ffmpeg.c`: демуксер продолжает читать сеть, когда голодает видео (а не только звук), в пределах удвоенных лимитов очереди.
- `stream_sync.c`: шлюз опережения звука 500 мс для passthrough mode 2.
- `stream_sink_video_android3.c`: сильно опоздавшие кадры (> 200 мс) сбрасываются сериями до 30 штук, затем один кадр показывается, чтобы картинка не замирала при постоянно отстающем декодере.
- `codec_sfdec2.c`: пересинхронизация после паузы при расхождении аудио и видео больше 500 мс в любую сторону.

## Обновление Nova до новой версии

1. Обновите upstream (`git pull`, новый тег/ветка) в корне и сабмодулях.
2. Примените патчи (скрипт идемпотентен и пропускает уже применённые):
   ```powershell
   .\apply_patches.ps1
   ```
   *(или в bash: `./apply_patches.sh`)*
3. Если патч не применился, разрешите конфликты в соответствующем репозитории.
4. Обновите upstream-ревизии (`*_BASE`) в `patches/export_patches.sh` и перегенерируйте патчи:
   ```bash
   bash patches/export_patches.sh
   ```
   Не сохраняйте `git diff` через `>` в PowerShell: получится UTF-16, который `git apply` не читает. Скрипт пишет патчи средствами git (UTF-8, LF), а `.gitattributes` запрещает git менять в них концы строк.
5. Прогоните тесты:
   ```powershell
   cd Video
   .\gradlew.bat -x ndkBuild :FileCoreLibrary:testDebugUnitTest :MediaLib:testDebugUnitTest :testNoamazonDebugUnitTest
   ```
6. Соберите APK:
   ```powershell
   $env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
   $env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
   $env:ANDROID_SDK_ROOT = "$env:LOCALAPPDATA\Android\Sdk"
   $env:Path = "$env:JAVA_HOME\bin;C:\w64devkit\bin;$env:Path"
   cd Video
   .\gradlew.bat assembleNoamazonRelease
   ```
   Готовый APK для ТВ (`armeabi-v7a`) появится в `Video\build\outputs\apk\noamazon\release\`.
